# План поэтапного клиентского калькулятора Tekstura

Этот PR — исследовательский UX-план и статический preview-макет. Он не внедряет новый калькулятор, не меняет рабочую страницу и не подключается к расчёту.

## Границы PR

- Не менять рабочий калькулятор и текущую страницу `calculator.html`.
- Не менять `stair-configurator.js`, `quantity-engine.js`, `quantity-engine-calculator-adapter.js` и Supabase migrations.
- Не менять клиентскую бизнес-логику цены и не возвращать старую pricing model.
- Не показывать клиенту коэффициенты, формулы и внутреннюю разбивку материалов/работ.
- Не трогать homepage и `index.html`.
- Не переносить UI из PR #46. Использовать только выводы: engine-first, UI-minimal, safe incremental rollout.

## Аудит текущего клиентского калькулятора

Текущий калькулятор уже построен вокруг инженерной логики: сначала сценарий и геометрия, затем материалы, потом стоимость и отправка на проверку. Проблема не в расчёте, а в плотности формы: клиент видит много инженерных понятий раньше, чем понимает, какие размеры нужны и где их измерить.

### Поля и выборы, которые сейчас есть

**Сценарий и форма лестницы**

- Что у вас уже есть: `Пустой проём`, `Готовое основание`.
- Тип готового основания: `Металлокаркас`, `Бетонная лестница`.
- Тип проёма: `Прямой`, `Г-образный`, `П-образный`, `Не выбран / не нужен`.
- Тип лестницы: `Прямая`, `Г-образная`, `П-образная`.
- Форма лестницы для готового основания: `Прямая`, `Г-образная с площадкой`, `Г-образная с забежными ступенями`, `П-образная с площадкой`, `П-образная с забежными ступенями`.
- Направление поворота: `Левый`, `Правый`.
- Тип поворота: `Площадка`, `Забежные ступени`.

**Основные размеры для нового проёма**

- Высота от пола до пола, мм.
- Длина проёма, мм.
- Ширина проёма, мм.
- Ширина марша, мм.

**Параметры готового основания**

- Количество ступеней.
- Ширина ступени, мм.
- Глубина ступени, мм.
- Высота подступенка, мм.
- Что отделываем: `Только ступени`, `Ступени + подступенки`, `Полная обшивка каркаса`.
- Количество листов материала.
- Размер листа, мм.
- Есть площадка.
- Длина площадки, мм.
- Ширина площадки, мм.
- Площадь площадки, м².
- Есть забежные ступени.
- Количество забежных ступеней.
- Дополнительная длина ограждения / балюстрады, м.

**Состояние основания**

- Состояние металлокаркаса: `Ровный`, `Нужна подгонка`, `Нужна покраска`, `Есть дефекты`.
- Комментарий по каркасу.
- Состояние бетонного основания: `Ровный`, `Перепады`, `Сколы`, `Нужна подготовка`.

**Материалы, регион и опции**

- Тип каркаса: `Металл`, `Дерево`, `Бетон`.
- Регион цены.
- Материал отделки: `Дуб / шпон`, `Ясень`, `Камень`, `Керамогранит`, `Микроцемент`.
- Ограждение: `Металл`, `Стекло`, `Дерево`, `Не нужно`.
- Покрытие / защита: `Стандартное`, `Премиальное`, `Не требуется`.
- Подсветка: `Не нужна`, `Точечная по ступеням`, `Линейная`.

### Что клиенту может быть непонятно

- Разница между `типом проёма`, `типом лестницы`, `формой готового основания` и `типом поворота`.
- Где измерять `длину проёма`, а где `доступное место по полу`.
- Чем `ширина проёма` отличается от `ширины марша` или `ширины ступени`.
- Что считать `забежными ступенями`: только поворотный узел или весь марш.
- Когда нужна `площадь площадки`, а когда достаточно длины и ширины.
- Что такое `дополнительная длина ограждения / балюстрады` и почему она вводится в метрах, а большинство размеров — в миллиметрах.
- Нужен ли клиенту `регион цены`, если он ожидает простой расчёт под ключ.
- Почему в одном шаге одновременно есть геометрия, материалы, покрытие, подсветка и служебные параметры готового основания.

### Что спрашивать поэтапно

1. Сначала определить ситуацию на объекте: пустой проём, готовый металлокаркас, бетонное основание, старая лестница / обшивка, консультация.
2. Затем выбрать понятную форму лестницы: прямая, Г-образная или П-образная; отдельно — площадка или забежные.
3. После этого запросить базовые размеры с визуальными подсказками: H, W, L, размеры проёма и примерное количество ступеней.
4. Только при нужном сценарии спросить площадку, забежные ступени и ограничения вокруг лестницы.
5. Затем перейти к материалу, отделке и ограждению.
6. В конце показать предварительный результат без инженерной формулы и без коэффициентов.

### Что скрывать в «Расширенные настройки»

- Регион цены, если он нужен системе, но не помогает клиенту понять лестницу.
- Тип каркаса для пустого проёма, если выбор не влияет на первичное UX-решение клиента.
- Подсветку и покрытие как вторичные опции.
- Количество листов материала и размер листа.
- Площадь площадки, если можно ввести длину и ширину.
- Дополнительную длину балюстрады, если клиент ещё не выбрал ограждение или не понимает верхнюю балюстраду.
- Комментарии по дефектам основания — оставить как необязательное поле после выбора готового основания.

### Что показывать только по сценарию

- Поля металлокаркаса показывать только для `готовый металлокаркас`.
- Поля бетонного основания показывать только для `бетонное основание`.
- Поля старой лестницы / обшивки показывать только для сценария обшивки.
- Поля площадки показывать только для форм `с площадкой`.
- Поля забежных ступеней показывать только для форм `с забежными`.
- Ограничения стен, окна или двери показывать после выбора формы лестницы и только как уточнение.
- Дополнительную верхнюю балюстраду показывать только если клиент выбрал ограждение и отметил, что оно нужно не только по маршу.

## Предлагаемая поэтапность

### Шаг 1. Что у вас сейчас?

Цель шага — убрать инженерные термины и начать с ситуации клиента.

Варианты:

- Пустой проём.
- Готовый металлокаркас.
- Бетонное основание.
- Старая лестница / нужна обшивка.
- Не знаю, нужна консультация.

UX-подсказка: если клиент выбирает «Не знаю», форма не должна блокировать заявку; нужно показать мягкий путь к консультации и попросить только фото/комментарий на следующих этапах.

### Шаг 2. Тип лестницы

Варианты:

- Прямая.
- Г-образная с площадкой.
- Г-образная с забежными.
- П-образная с площадкой.
- П-образная с забежными.

UX-подсказка: карточки должны объяснять форму простыми схемами сверху, без 3D и без технических рендеров.

### Шаг 3. Основные размеры

Поля:

- Высота от пола до пола.
- Ширина марша.
- Длина проёма.
- Ширина проёма.
- Примерное количество ступеней, если известно.

Визуальные подсказки:

- «Высота H — от чистого пола первого этажа до чистого пола второго».
- «Ширина W — полезная ширина лестницы».
- «Длина L — доступное место по полу».

UX-подсказка: поля должны быть крупными, с единицами измерения рядом с вводом, а не спрятанными в тексте label. Если размер неизвестен, должна быть опция «уточним на замере».

### Шаг 4. Площадка / забежные / ограничения

Показывать только если выбран соответствующий тип лестницы.

Поля:

- Есть ли площадка.
- Примерный размер площадки.
- Есть ли стены сбоку.
- Есть ли окно/дверь рядом.

UX-подсказка: для прямой лестницы этот шаг можно пропустить или показать как короткий блок «Ограничения рядом».

### Шаг 5. Материал и отделка

Варианты:

- MDF под покраску.
- Дерево.
- Комбинированный вариант.
- Нужна консультация.

UX-подсказка: не показывать внутренние rate keys, коэффициенты и технические настройки каталога. Клиент выбирает понятный внешний вариант, а runtime settings остаются внутри системы.

### Шаг 6. Ограждение

Варианты:

- Без ограждения.
- Металл.
- Стекло.
- Дерево.
- Комбинированное.

Подсказка на шаге: «Ограждение считается по длине марша и верхней балюстраде, если она нужна.»

UX-подсказка: сначала спросить тип ограждения, затем мягко уточнить открытую сторону и верхнюю балюстраду через схему. Не просить клиента сразу вводить техническую длину, если он её не знает.

### Шаг 7. Итог

Показать:

- Предварительная стоимость под ключ.
- Состав: ступени, подступенки, площадки, покрытие, расходники, ограждение.
- Нейтральный текст: «Финальная смета уточняется после проверки размеров».
- Кнопка заявки.

Не показывать:

- Коэффициенты.
- Формулы.
- Внутреннюю разбивку материалов/работ.


## Визуальный стиль preview

Preview оформлен как premium dark UI mockup, чтобы согласовывать не только структуру шагов, но и ощущение будущего клиентского интерфейса.

- Основной фон почти чёрный, с мягкими градиентами и большим количеством воздуха.
- Акцент Tekstura — золото: используется для выбранных карточек, стрелок направления, важных зон площадки/забежных ступеней и CTA.
- Карточки крупные, с тонкими рамками, мягкими тенями, hover/selected состояниями и понятными короткими подписями.
- Step 2 считается ключевым экраном выбора формы лестницы: клиентские карточки выбора используют крупные raster visual hints (`.png`) для прямой, Г-образной, П-образной лестницы, площадки и забежных ступеней.
- Raster-картинки нужны там, где клиенту важнее быстро распознать форму, чем читать технический чертёж: выбор формы лестницы, площадка и забежные ступени.
- SVG остаются для точных технических подсказок: размеры H/W/L, ограждение по открытой стороне и fallback-схемы. Такие SVG должны быть локальными, без base64, CDN и внешних ссылок.
- Визуальные подсказки шага 2 не должны быть фотореализмом: допустима аккуратная 2.5D / technical illustration с тёмным фоном, золотыми акцентами, крупными ступенями и без мелкого текста внутри картинки.
- Визуальный direction можно использовать только как preview-ориентир; внедрение в рабочий калькулятор должно оставаться engine-first, UI-minimal и safe incremental rollout.

## Как внедрять безопасно

### PR 1: `calculator-stepwise-preview`

- Только static preview.
- Не подключать preview к рабочему калькулятору.
- Не менять `calculator.html`, `stair-configurator.js`, engines и migrations.

### PR 2: `calculator-stepwise-state-shell`

- Добавить wizard state рядом с текущим UI.
- Не менять расчёт.
- Не менять contract с Geometry Engine и Quantity Engine.
- Сохранить возможность отката к текущей форме.

### PR 3: `calculator-stepwise-fields`

- Перенести текущие поля по шагам.
- Не менять названия данных, которые нужны адаптеру расчёта.
- Добавить условный показ полей по сценарию.

### PR 4: `calculator-stepwise-visual-hints`

- Использовать WebP/PNG visual hints для клиентских карточек выбора формы.
- Оставить SVG для технических подсказок к измерениям и ограждению.
- Не подменять raster-изображения декоративными CSS-линиями.
- Не внедрять 3D, premium renderer или visual configurator.

### PR 5: `calculator-stepwise-runtime-integration`

- Подключить wizard к существующим Geometry Engine и Quantity Engine.
- Проверить, что runtime settings Supabase продолжают управлять материалами и ограждениями.
- Не показывать клиенту коэффициенты, формулы и внутреннюю модель цены.

### PR 6: `calculator-stepwise-mobile-polish`

- Мобильная полировка.
