# Codex Project Rules — Tekstura

Репозиторий: `vladimi251077/stairs-site`  
Основная ветка: `main`  
Основной деплой: Vercel. Netlify не считать основным деплоем, если отдельно не сказано обратное.

## Цель

Сделать сайт Tekstura премиальным, понятным и продающим для заказчиков лестниц, не ломая калькулятор, заявки, админку и существующие данные.

Tekstura — премиальные лестницы, производство, инженерия, дерево, металл, отделка и монтаж.

## Общие правила

- Все отчёты, комментарии и PR descriptions писать на русском.
- Один PR = одна маленькая понятная задача.
- Не делать задач вида «улучшить весь сайт».
- Не мержить PR самостоятельно.
- Если PR реально не создан, не писать «готово».
- Настоящий PR должен иметь ссылку вида `https://github.com/vladimi251077/stairs-site/pull/номер`.

## Запрещено без отдельного разрешения

- Менять backend/API отправки заявок.
- Менять Supabase-схему и миграции.
- Менять формулы калькулятора.
- Менять инженерную диагностику калькулятора: `diagnostics`, `alternatives`, `headroom`, `fit`.
- Удалять существующие поля калькулятора.
- Менять логику отправки заявки в `request.html`.
- Трогать unrelated файлы.
- Делать большой рефакторинг.
- Добавлять тяжёлые библиотеки.
- Добавлять бинарные файлы без отдельного согласования.

## Визуальный стиль

Цель: премиум, архитектурность, дерево, металл, тёмный спокойный фон, сдержанные акценты, инженерная надёжность.

Избегать:

- дешёвых шаблонных эффектов;
- случайных ярких цветов;
- лишних анимаций;
- тяжёлых визуальных библиотек;
- дизайна, который ухудшает читаемость или скорость.

## Перед изменениями

Перед изменением кода написать:

1. Какая задача выполняется.
2. Какие файлы планируется трогать.
3. Какие файлы точно не трогать.
4. Какие риски есть.
5. Как будет проверяться результат.

Если задача аналитическая — код не менять и PR не создавать.

## После изменений

После изменений дать:

1. Summary.
2. Список изменённых файлов.
3. Что специально не менялось.
4. Как проверить вручную.
5. Какие проверки выполнены.
6. Ссылку на PR.

## Роли для задач

### Аналитик конкурентов

Код не менять. PR не создавать.

Нужно анализировать сильные сайты по темам: премиальные лестницы, лестницы на заказ, деревянные лестницы, металлокаркас + дерево, лестницы Казань/Москва/Россия, премиальные интерьерные студии, архитектурные мастерские.

Результат: отчёт, сильные решения, что перенять для Tekstura, что не копировать, список маленьких будущих PR.

### Аудитор сайта

Код не менять. PR не создавать.

Проверить: главную, проекты, услуги, калькулятор, заявку, мобильную версию, ассеты, доверие клиента и структуру. Найти слабые места и предложить следующие PR по приоритету.

### Арт-директор / дизайнер

Код не менять. PR не создавать.

Сформировать дизайн-концепцию: цвета, типографика, кнопки, карточки, hero, проекты, калькулятор, заявка, мобильная версия, стиль фото и SVG-схем.

### Разработчик

Делать только одну конкретную задачу. Один PR. Маленький diff. Не менять backend, Supabase, расчёты калькулятора и unrelated файлы. Не добавлять binary files без разрешения. Не мержить.

### QA-проверяющий PR

Код не менять. PR не создавать.

Проверить changed files, риски, мобильную версию, Vercel Preview, отсутствие изменений backend/Supabase/логики калькулятора. Дать вывод: можно мержить / нельзя / можно после ручной проверки.
